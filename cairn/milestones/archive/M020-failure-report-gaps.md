# M020: Close the gaps in CI failure reports

**Status:** done (2026-10-21, PR #31 https://github.com/jmgirard/rstudio2u/pull/31)

**Goal:** Every way a scheduled job can fail reaches the `ci-failure` issue with the job named, and the rebuild-gap check's lookup is tested.

**Outcome:** `.github/ci-failure-issue.sh`'s `extract_failed_names` selects conclusion `failure` or `timed_out`, so a timed-out job or leg is named (a leg by its variant, once) instead of falling back to generic text with a contradiction warning. `rebuild-gap.yml` gained a `notify` job: `needs: gap`, runs only on a scheduled run whose `gap` result is `failure`, and hands `gh run view --json jobs` to the failure script, so the issue reads "Weekly run failed: rebuild-gap"; it never closes the issue, and while the check stays broken the Monday rebuild closes it and a new one opens each week (stated in the job's comment). The `gh run list` lookup and its four outcomes (date, `none`, `unknown` for an unparseable answer or a failed lookup) moved from YAML into `.github/last-rebuild-success.sh <output-file>`, which writes the word to a file so its `::warning::` lines reach the log; `scripts/tests/test_last_rebuild_success.sh` (23 assertions) runs in `pr-ci.yml`. `docker.yml`: `.github/ci-failure-issue.sh` joined `on.push.paths` (a change to it now rebuilds and publishes, though a push run never runs the script), and `meta`, `build`, `publish` carry `permissions: contents: read`, proved by test-mode dispatch 39533199085. No user-visible change: the image and its tags are unchanged.

**Decisions:** none. The plan gate chose a separate lookup script over feeding a reduction function from YAML, a failure-only `notify` over one passing every result (a `success` would close the gap issue), and `contents: read` alone for the three jobs.

All five criteria verified fresh; no amendments.
