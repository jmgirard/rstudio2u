# M021: Refuse to move moving tags backward

**Status:** done (2026-10-20, PR #32 https://github.com/jmgirard/rstudio2u/pull/32)

**Goal:** A publish leg does not move a tag to an index stamped earlier than the index the tag points at when the leg reads it.

**Outcome:** `docker.yml`'s `meta` job reads the clock once and outputs a run `stamp` (`YYYY-MM-DDTHH:MM:SSZ`, UTC), and `date` is its date part. Both `imagetools create` calls in `publish` pass one `create_args` array with the index annotation `org.opencontainers.image.created=<stamp>`. Before the dry run, `publish` (now with a checkout) runs `.github/tag-order.sh <stamp> <out-file> <ref>...`, which reads each tag with `imagetools inspect --raw`. A tag on a later-stamped list is left out with a `::warning::`. A tag that is absent (only buildx's exact `ERROR: docker.io/<ref>: not found` line), unstamped, or stamped equal or earlier is kept. Any other read (another registry error, not JSON, not an index, annotations that are not an object, a stamp not in the fixed form, a bad run stamp) exits 1 and fails the leg before any tag moves. The leg attaches only the kept tags and skips the create when none are kept. `scripts/tests/test_tag_order.sh` (91 assertions, per-ref `docker` stub) runs in `pr-ci.yml`, and `tag-order.sh` joined both workflows' `paths`. A `cairn/DESIGN.md` Conventions bullet states the rule, its six bounds, and the hand re-point command. Test-mode dispatch 39536881154 showed the stamp on both variants' dry-run lists. User-visible change: a "Re-run failed jobs" of an older build can no longer move `latest`, `noble`, `resolute`, or the date and version tags back to older images. Protection starts with each tag's first stamped publish.

**Decisions:** none. The plan gate chose an index annotation holding the `meta` stamp over the image config's `created` time and over listing Docker Hub tags. It chose per-tag refusal over refusing the whole leg (GP2), failing on a malformed stamp over reading it as unstamped, and recording the cross-run race as a bound over a `concurrency:` group.

**Review:** four-lens fan-out plus a 31-claim pre-review claim audit (6 corrected, among them a code gap: non-object annotations had read as unstamped). 22 review findings: 13 fixed on the branch (`annotations: false/null`, the recovery command, the ERROR-line cause, test gaps, test-mode output, and stale comments), 4 follow-ups (candidate rows "Refuse tag stamps later than the clock", "Retry the tag-order registry reads", "Run the empty attach path in CI"), and 5 rejected (the race and the checkout were planned, plus three false or already handled). All six criteria verified fresh. No amendments. Graduated the candidate row "Refuse to move moving tags backward". No lesson captured: the buildx not-found behavior is recorded in `tag-order.sh`'s comments.
