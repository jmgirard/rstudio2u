# M023: Re-print the offline warning at the end

**Status:** done (2026-11-05, PR #34 https://github.com/jmgirard/rstudio2u/pull/34)

**Goal:** A student whose launcher skipped the image update can still read that fact after the server is ready.

**Outcome:** User-visible: when the image download fails and a copy is on disk, all three start launchers repeat a reminder after the running banner, open the browser, say "RStudio keeps running after you close this window.", and wait for a key press. A start whose download works behaves as before, and a start whose server fails prints the warning once. `launcher_remind_offline` and `launcher_hold_offline` in `launcher_common.sh`, `update_skipped` in the POSIX launchers (which `exit 0` after the hold, because `read` returns 1 at end of input), `UPDATE_SKIPPED` in `start_windows.bat`, whose `goto :done` under the seam became a guard around the browser lines only. `launcher_pause` and `:wait` print `[test seam] key wait skipped` under the seam. Both harnesses gained order and count checks and an `offline-health-timeout` scenario. README FAQ updated.

**Decisions:** none. Plan gate: repeat and hold over repeat only, because a Windows window closes about 3 seconds after the banner; a seam marker over driving the launchers without the seam, because `start` and `timeout` cannot run unattended in CI.

**Review:** Four-lens fan-out, 27 findings: 4 fixed (comments naming a false reason, a comment restating code, the order check now asks for `Reminder:`, a stale harness header), 5 to 3 parked rows ("Drop keys typed before the key wait", "Reword the launcher key-wait prompt", "Name other causes of a failed pull"), 18 rejected, 2 of those as edge (an open non-terminal stdin or wrapper blocks at the wait; `start_mac.command`'s exit status no longer follows a failed `open`). The claim audit found the source row's premise did not hold where measured: on a Mac with Compose 5.6.1 in a pseudo-terminal, `up -d --wait` redraws in place, so the first warning stays on a 24-row window; the goal stands on the Windows close and browser focus. Evidence: POSIX harness local; PR head run passed all five checks; temporary branch `m023-windows-probe`, approved at a stop and deleted, showed 11 of 11 planted Windows defects red (POSIX 10 of 10 local); a pseudo-terminal probe ran the real key wait on macOS. No test presses a real key on Windows, by the user's choice at the question set. Row "Re-print the offline warning at the end" graduated.
