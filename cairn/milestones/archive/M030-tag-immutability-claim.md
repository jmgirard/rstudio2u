# M030: Stop calling the Docker tags immutable

**Status:** done (2026-11-06, PR #45 https://github.com/jmgirard/rstudio2u/pull/45)

**Goal:** The README, `cairn/DESIGN.md`, and the publish workflow's comments say truthfully which Docker tags can move, so a user who pins one for reproducibility gets what the text promises.

**Outcome:** Text only, no image change. The README's Reproducibility section says moving tags move on each rebuild, the weekly one included. A `<variant>-<date>` tag names the UTC date its build started and moves to a later build with the same date. A `<variant>-<rstudio>` tag moves with each newer build while that RStudio version is the newest stable. A digest pin never moves and gets no security updates. The section shows the read (`docker buildx imagetools inspect <tag>`, its `Digest:` line, with `docker pull <tag>` as a fallback), the `image: jmgirard/rstudio2u@<digest>` Compose pin (start without `--build`, which stops with "build tag cannot contain a digest"), and the `FROM` pin, whose installed packages still float (renv). README line 19, line 21, and the Baking section point to digests. GP2 takes the D-015 wording. DESIGN Purpose & Scope, "Two version records", and the tag-order bounds drop "immutable" or the "each run's date tag is new" claim, marked corrected M030. Comments in `docker.yml` and `pr-ci.yml` drop "immutable". Merging touched `docker.yml`, so it started a publish. User-visible change for the next release's notes: the README now teaches digest pins and says which tags move.
